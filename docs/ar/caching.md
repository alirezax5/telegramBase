# التخزين المؤقت (كاش) — CacheManager

واجهة API ثابتة واحدة فوق أربعة مُشغِّلات قابلة للتبادل، تُضبط بالكامل عبر `.env`. الجلسات والترجمات وتعريفات الأزرار و(اختياريًا) اكتشاف الإضافات كلها تركب على هذه الطبقة — تغيير المُشغِّل يغيّر قصة التخزين الدائم للإطار كله دون لمس الكود.

```php
use alirezax5\TelegramBase\App\Cache\CacheManager;
```

> كل ادعاء في هذه الوثيقة جرى التحقق منه مباشرة (2026-10-11) مقابل واجهات خلفية حقيقية على خادم إنتاجي: مجموعة الفحوصات ذات الـ 17 فحصًا نجحت على `array` و`file` و`memcached` (PHP 8.5) و`redis`، إضافة إلى مصفوفة استمرارية عبر العمليات من 9 نقاط لكل مُشغِّل دائم. انظر قسم *التحقق المباشر* في الأسفل و[CHANGELOG](../../CHANGELOG.md).

## المُشغِّلات

| `CACHE_DRIVER` | الواجهة الخلفية | عبر العمليات | الوسوم | ملاحظات |
|---|---|---|---|---|
| `array` (الافتراضي) | ذاكرة لكل عملية | ✗ | ✗ | بلا إعدادات؛ تعيش الحالة بقدر عمر العملية بالضبط |
| `file` | القرص، `CACHE_PATH` | ✓ | ✗ | بلا خدمات إضافية؛ مجلدات بمستويين مُلبَّدة الأسماء؛ حمولات مُسلسَلة بـ PHP |
| `redis` | امتداد phpredis (`redis.so`) | ✓ | ✗ | حمولات JSON؛ موصى به لنشريات متعددة العمليات |
| `memcached` | امتداد `memcached` + خادم | ✓ | ✗ | حمولات JSON؛ متطاير بطبيعته |

**سلسلة الرجوع (مُتحقَّق منها):** إذا كان المُشغِّل المطلوب غير متاح — امتداد مفقود، أو خادم لا يمكن الوصول إليه، أو فشل مصادقة، أو مسار غير قابل للكتابة — يسجّل الإطار تحذيرًا و**يعود إلى `array`** بدلًا من إخفاق الإقلاع. طلب `memcached` على PHP بلا الامتداد أنتج بالضبط هذا: `driver=array`، وكل ما عدا ذلك دون تغيير. تحقّق مما حصلت عليه فعلًا عبر `CacheManager::getDriver()`.

> ⚠️ مُشغِّل `array` محلي للعملية. شيطان الاستطلاع هو *عملية* واحدة طويلة العمر، لذا «يعمل» `array` هناك؛ لكن الويب هوك (عمال FPM لكل طلب) وعمال قائمة الانتظار (عملية لكل عامل) لا يتشاركان الحالة أبدًا. إذا كانت الجلسات أو العدّادات أو `remember()` تحتاج إلى النجاة عبر الرسائل/العمليات، فاستخدم `file` أو `redis` أو `memcached`. دُلِّل على ذلك مباشرة: قيم كُتبت في العملية A وقُرئت في العملية B — تدوم على الثلاثة جميعًا، و`<MISS>` على `array` (بالتصميم).

## الإعدادات (.env)

```dotenv
CACHE_DRIVER=file            # array | file | redis | memcached
CACHE_PREFIX=tgbase_         # key namespace (also the flush() safety boundary)
CACHE_TTL=3600               # default TTL seconds when put() has no explicit ttl
CACHE_PATH=/tmp/tgbase-cache # file driver only
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=              # required if the server has requirepass (NOAUTH otherwise)
REDIS_DATABASE=0
MEMCACHED_HOST=127.0.0.1
MEMCACHED_PORT=11211
```

## واجهة الـ API

| الدالة | السلوك |
|---|---|
| `get($key, $default = null)` | القيمة أو الافتراضي عند الغياب/الانتهاء |
| `put($key, $value, ?int $ttl = null)` | تخزين؛ مهلة `null` ← `CACHE_TTL` |
| `remember($key, callable $cb, ?int $ttl = null)` | إعادة القيمة المخزنة أو تنفيذ `$cb` وتخزين النتيجة |
| `has($key)` | موجود وغير منتهٍ |
| `forget($key)` | حذف مفتاح واحد |
| `flush()` | حذف **كل مفاتيح نطاق هذا الإطار** — انظر ملاحظات كل مُشغِّل |
| `increment($key, $by = 1)` / `decrement($key, $by = 1)` | العدّادات |
| `getDriver()` / `isInitialized()` / `tagsSupported()` | الاستبطان |
| `putWithTags()` / `getWithTags()` / `rememberWithTags()` / `flushTags()` | واجهة API على نمط الوسوم تعمل مع كل مُشغِّل (رجوع قائم على البادئة) |
| `tags([...])` | كاش ذو وسوم أصلي — **يرمي استثناءً** ما لم يدعم المُشغِّل الوسوم (ولا واحد من الأربعة يدعمها) |

### دلالات TTL (مُتحقَّق منها بانتظار حقيقي)

`put('k', 'x', 2)` ← `has` صحيح ← بعد 3 ثوانٍ ← `has` خاطئ، و`get` يعيد الافتراضي. مهل الواجهات الخلفية تطابق الإعدادات تمامًا: أظهرت مدخلة مدتها 300 ثانية ‏`ttl=297s` تحت `redis-cli`، وجلسة مدتها 3600 ثانية ‏`ttl=3597s`، وكاش ترجمات مدته 60 ثانية ‏`ttl=57s`. المدخلات المنتهية في `file`/`redis` تُزال بشكل مؤجل (عند الوصول) أو بواسطة الواجهة الخلفية (`setex` في `redis`).

### صيغ التخزين

- **redis** — ‏`setex` مع `json_encode(JSON_UNESCAPED_UNICODE)`. يجب أن تكون الحمولات قابلة للمرور عبر JSON ذهابًا وإيابًا: العددات والمصفوفات نعم؛ وكائنات PHP تعود كمصفوفات؛ ولا موارد (resources).
- **memcached** — JSON عبر عائلة التخزين نفسها؛ القيم تُسلسَل وتُفكّ تسلسلها بشفافية من الامتداد.
- **file** — حمولات `serialize()` بـ PHP، وختم الانتهاء أولًا، تحت `CACHE_PATH/ab/cd/<sha1>`.
- **array** — متغيرات PHP مجردة؛ لا شيء يلمس القرص أو الشبكة.

### تخطيط المفاتيح (المنظر الخام للواجهة الخلفية)

| المُشغِّل | المفتاح الخام لـ `put('lang:fa', …)` مع `CACHE_PREFIX=tgbase_` |
|---|---|
| redis | `tgbase_lang:fa` |
| memcached | `tgbase_:lang:fa` (يلحق Illuminate ‏`:` بالبادئة) |
| file | `CACHE_PATH/<h1>/<h2>/<sha1>` |

### العدّادات — ملاحظة دقيقة واحدة (مُتحقَّق منها)

`increment()` على مفتاح **مفقود**: ينشئه `array`/`file`/`redis` (عبر `incBy`)، بينما يعيد `memcached` ‏`false` (لا يرسل Illuminate قيمة أولية). النمط المحمول: بذِّر أولًا — `CacheManager::put($k, 0, $ttl); CacheManager::increment($k);`

### ‏flush() — نطاق الوصول لكل مُشغِّل

- `array` — هذه العملية فقط.
- `file` — كل ما داخل `CACHE_PATH` (مجلد مخصص؛ آمن).
- `redis` — **مقيّد بالبادئة**: يكرر `SCAN` على `{CACHE_PREFIX}*` وينفّذ `UNLINK` على تلك المفاتيح فقط. آمن على النسخ المشتركة (تحقّق منه على Redis مشترك مع كاشات كائنات WordPress — لم تُلمَس المفاتيح الأخرى). يرفض العمل ببادئة فارغة.
- `memcached` — ⚠️ يُصدر `MemcachedStore::flush()` أمر `flush_all` على كامل الخادم. على memcached **مشترك** يمحو هذا كاش التطبيقات الأخرى — تجنّبه هناك (مجموعة الاختبارات تتجنّبه عمدًا).

## ما الذي يركب على الكاش

| المستهلك | المفتاح | مقبض TTL |
|---|---|---|
| [الجلسات](sessions.md) | `tgbase:session:{chatId}` | `SESSION_TTL` (الافتراضي 3600، الحد الأدنى 60) |
| [الترجمات](i18n.md) | `lang:{lang}`، `lang:missing_keys` | `LANG_CACHE_TTL` (الافتراضي 60) |
| [تعريفات الأزرار](buttons.md) | `buttons:all` | `BUTTONS_CACHE_TTL` (الافتراضي 300)، ومفتاح الإيقاف `BUTTONS_CACHE_ENABLED` |
| اكتشاف الإضافات | (داخلي) | `PLUGIN_CACHE_ENABLED` + `PLUGIN_CACHE_TTL` |

## التحقق المباشر (P-CACHE، 2026-10-11)

| المجموعة | النتيجة |
|---|---|
| المجموعة داخل العملية ذات الـ 17 فحصًا × ‏`array` / `file` / `memcached` (PHP 8.5) / `redis` | **PASS** على جميعها |
| طلب memcached على PHP 8.4 (بلا امتداد) ← رجوع سلس إلى `array` | **PASS** (السلسلة الموثّقة) |
| مصفوفة عبر العمليات (`set` في عملية ← `get` في عملية أخرى): عدد، مصفوفة متداخلة، عدّاد 5→6، `remember` يعيد العشوائية *المزروعة*، استمرارية معرف الجلسة وحمولتها، حمولة `lang:fa`، حمولة `buttons:all` | **9/9 PASS** على `file` و`redis` و`memcached`؛ و`array` يُخفق تمامًا كما هو موثّق |
| فحص الواجهات الخلفية | مفاتيح redis مع عدّ TTL حي؛ مفاتيح memcached الخام تحت `tgbase_:`؛ مخزن الملفات بأختام انتهاء ظاهرة |
| خط معالجة حقيقي: `/cache demo hello` (توزيع 1) ← `/cache demo` (توزيع 2، عملية جديدة) ← ‏`demo = hello`؛ وكذلك `/session-set`/`/session-get` | **PASS** |

كشف هذا التمرين عيبًا حقيقيًا واحدًا وأُصلح بسببه: **كان `CacheRedisStore::flush()` يُنهي حلقة SCAN عند أول صفحة MATCH فارغة** (أمر شائع على فضاءات المفاتيح المشتركة/الكبيرة) — فيحذف لا شيء ويعيد `true` (P-CACHE-F001 في CHANGELOG).
