# تعدد اللغات (i18n) — Language

ملفات الترجمة، والدالة المساعدة `__()`، والتخزين المؤقت التلقائي لخرائط اللغة المُصرَّفة.

```php
use alirezax5\TelegramBase\App\Language\Language;
```

## تخطيط الملفات

كل شيء يسكن تحت `LANG_DIR` (الافتراضي `/Language`، يُحلّ نسبةً إلى جذر المشروع — يوصّل لك `Bootstrap` المسار `Paths::base() . LANG_DIR`).

```
Language/
├── fa.php            # main file for 'fa' — keys as-is
└── fa/               # optional subdirectory — keys get a '<filename>.' prefix
    ├── main.php      #   → main.ali, main.other, …
    └── buttons.php   #   → buttons.save, buttons.cancel, …
```

- **الملف الرئيسي** هو `{LANG_DIR}/{lang}.php`؛ أما **المجلد الفرعي** فهو `{LANG_DIR}/{lang}/` وكل ملف فيه يُحمَّل أبجديًا مع استخدام اسم الملف الأساسي بادئةً للمفتاح.
- المصفوفات المتداخلة تُسطَّح إلى **ترميز النقاط**: ‏`['btn' => ['btna' => 'hi']]` ← `btn.btna`.
- تنسيق الملف يتبع `LANG_DRIVER`:

> ⚠️ **يجب أن يطابق `LANG_DRIVER` تنسيق ملفاتك.** الافتراضي هو `json`، لكن المستودع يشحن ملفات مصفوفات PHP (‏`fa.php`، و`fa/main.php`) و`.env.example` يضبط `LANG_DRIVER="php"`. مع عدم التطابق (مُشغِّل json + ملفات .php) يعود كل بحث بصمت إلى اسم المفتاح — لا خطأ، فقط نص غير مترجم. أُعيد إنتاج هذا السيناريو بالضبط أثناء اختبارات P-CACHE المباشرة: أعاد `__('key')` القيمة `"key"` حتى ضُبط `LANG_DRIVER=php`.

```dotenv
LANG_DRIVER=php        # json | php — format of the language files
DEFAULT_LANG=fa        # boot language (Persian, RTL)
LANG_DIR=/Language
LANG_CACHE_TTL=60      # seconds the compiled map stays in cache
```

## الدالة المساعدة `__()`

```php
// translations: 'welcome' => 'سلام #name خوش آمدی'
__('welcome', ['name' => 'علی']);          // "سلام علی خوش آمدی"
__('missing_key', 'پیش‌فرض');              // fallback when the key is absent
__('missing_key');                          // falls back to the key name itself
```

الاستبدالات تستخدم صيغة `#placeholder`؛ وتُكتب مفاتيح الخريطة دون `#`:

```php
__('greeting', 'default', ['name' => $firstName, 'count' => 3]);
```

النمط الأحادي لـ Language:

```php
$lang = Language::getInstance();

$lang->setLanguage('en');        // switch language (per process — call it per update if users differ)
$lang->get('key', $default, $replacements);
$lang->has('key');               // exists in the current language?
$lang->getAll();                 // full flat map
$lang->getCurrentLanguage();

$lang->reloadLanguage('fa');     // drop cache + re-read files
$lang->clearCache();             // forget lang:* cache keys
$lang->getCacheStats();          // per-language entry counts + freshness
```

## لغة كل مستخدم داخل إضافة

‏`Language` نمط أحادي لكل عملية — اللغة الحالية تنطبق على كل ما يعمل بعد `setLanguage()` في تلك العملية. لاختيار لغة لكل مستخدم (نشرات الويب هوك/قائمة الانتظار)، افصل اللغة واضبطها في أعلى المعالج:

```php
$userLang = $session->get('lang', 'fa');          // or read from your users table
Language::getInstance()->setLanguage($userLang);
$tg->sendMessage($chatId, __('menu_title'));
```

في شيطان استطلاع أحادي العملية، يتسرب التبديل في منتصف تحديث إلى التحديثات اللاحقة ما لم تعد بالتبديل — يُفضَّل ضبطه لكل تحديث دون شرط.

## سلوك التخزين المؤقت (مُتحقَّق منه)

تحميل اللغة الأول يقرأ الملفات، ويُسطّح الخريطة، ويخزنها تحت مفتاح الكاش `lang:{lang}` مع `LANG_CACHE_TTL`. التحميلات اللاحقة (بما فيها العمليات الجديدة) تصطدم بالكاش — أظهر تشغيل P-CACHE الحمولة الكاملة (`{"key":"value","btn.btna":"hi","main.ali":"asfaf132"}`) ناجيةً عبر العمليات على `file` و`redis` و`memcached`، مع عدّ TTL في الواجهة الخلفية نازلًا من 60 ثانية بالضبط. تُتتبَّع مفاتيح الترجمة المفقودة في `lang:missing_keys` وتُفرَّغ مرة واحدة لكل تكرار تحديث (`Core::cleanup()` ← `flushMissingKeys()`)، ما يجعل تنقيح النصوص غير المترجمة أمرًا تافهًا — افحص الكاش/السجلات لقائمة المفاتيح.

## توليد الهياكل

```bash
php bin/tgbase make:language en     # creates Language/en.php scaffold
```

يُظهر `Language/fa.json.example` تنسيق JSON إن كنت تفضل ملفات JSON (وعندها اضبط `LANG_DRIVER=json`).
