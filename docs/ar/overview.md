# نظرة عامة — ما هو TelegramBase

## الصيغة المختصرة في جملة واحدة

TelegramBase هو إطار عمل بلغة PHP يحوّل «التحدث إلى Telegram Bot API» إلى «كتابة أصناف إضافات صغيرة»، بينما يتولى بنفسه كل ما تحتاجه البوتات الموثوقة: جلب التحديثات، والتحقق من صحة الويب هوك، ووضع العناصر في قوائم الانتظار، وإعادة المحاولة، ودورة حياة العمليات.

## ما الذي يفعله

كل بوت على Telegram — مهما كان بسيطًا — يحتاج إلى الهيكل العظمي ذاته:

1. **استقبال التحديثات.** إمّا أن تسأل Telegram «هل من جديد؟» (الاستطلاع الطويل long-polling عبر `getUpdates`)، أو أن يتصل Telegram بعنوان HTTPS الخاص بك (ويب هوك). يدعم TelegramBase كلا الأسلوبَين، ويُحدَّد الاختيار بقيمة واحدة في `.env`.
2. **التحقق من صحة طلبات الويب هوك.** يستطيع أي شخص إرسال POST بتحديثات مزيفة إلى عنوانك. يتحقق TelegramBase من حجم الجسم، وعنوان IP المصدر (شبكات Telegram الرسمية الفرعية)، ورمز سري اختياري، وسلامة بنية JSON قبل أن يُنفَّذ كودك أصلًا.
3. **توجيه التحديثات إلى كودك.** يقوم `Processor` بتوحيد شكل كائن التحديث الخام ثم يسلّمه إلى كل إضافة تتطابق مرشّحاتها (نوع المحادثة، ترتيب الأولوية)، اختياريًا عبر خط أنابيب من الوسطاء البرمجيين.
4. **البقاء قائمًا عند الفشل.** قد تُعيد استدعاءات الـ API الرمز `429 Too Many Requests`. قد تُلقي المعالجات استثناءات. قد تُقتَل عمال المعالجة في منتصف تحديث. قد تتعطّل وسطاء قوائم الانتظار. أمام كل حالة من هذه لدى TelegramBase خطة: قائمة إعادة محاولة بتراجع أُسّي (مع احترام `retry_after` الخاص بـ Telegram)، وأحجام قوائم انتظار محدودة، وإعادة اتصال بالوسيط بتراجع تدريجي، وضمانات توصيل موثّقة لكل وضع على حدة.
5. **التوسّع عند الحاجة.** ابدأ بعملية واحدة `php bot.php`. وعندما يثقل عبء المعالجة، انتقل إلى خط أنابيب قائمة انتظار: جالب خفيف يدفع التحديثات إلى Redis/RabbitMQ وعمليات عمال منفصلة تستهلكها.

يفعل TelegramBase كل ذلك ويكشف واجهة API صغيرة، بسيطة لا مفاجآت فيها، وقابلة للاختبار.

## ما الذي لا يفعله عمدًا

- **ليس SDK لبوتات Telegram.** الاستدعاءات الفعلية لـ Telegram API تأتي من [`alirezax5/telegram-bot-php`](https://github.com/alirezax5/telegram-bot-php) (الكائن `Telegram` المحقون في إضافاتك). أما TelegramBase فهو الطبقة *المحيطة* بذلك الـ SDK.
- **لا يكتب منطق بوتك عنك.** لا يوجد «منشئ محادثات» ولا لوحة إدارية. أنت تكتب أصناف PHP عادية؛ والإطار هو من يجدولها ويغذّيها.
- **لا يُخفي PHP.** لا لغة وصف مخصصة (DSL)، ولا تعريفات بوت بصيغة YAML. إن كنت تعرف PHP 8 و Telegram Bot API، فأنت تعرف كيف يعمل TelegramBase.

## فلسفة التصميم

- **الإعدادات قبل الكود.** وضع التشغيل، ووسيط قوائم الانتظار، ومشغّل ذاكرة التخزين المؤقت (كاش)، واللغة — تُبدَّل جميعها عبر `.env` دون تعديل الأصناف.
- **مكوّنات بسيطة مجرّبة.** الجلسات وذاكرة التخزين المؤقت والأقفال مبنية على Illuminate (`illuminate/cache`, `illuminate/database`). وهي المكوّنات ذاتها التي يستخدمها Laravel في الإنتاج؛ ولا يضيف TelegramBase أي تبعيات غريبة.
- **الصراحة بشأن الفشل.** لكل مسار معالجة ضمانة توصيل موثّقة (at-least-once أو at-most-once) — قيست بقتل عمال حقيقيين بـ SIGKILL أثناء الاختبارات التكاملية، لا بالتخمين. انظر [reliability.md](reliability.md).
- **افشل بصوت مسموع لا بصمت.** وضع CLI فقط على نقطة دخول ويب يُعيد HTTP 500 مع شرح، بدلًا من التعليق بصمت. وقائمة انتظار ممتلئة ترفض وتسجّل عمليات الدفع الجديدة بدلًا من ابتلاع مساحة قرصك.

## شكل قاعدة الكود

```
App/          the framework (one concern per subdirectory)
Plugin/       YOUR plugins (auto-discovered)
Button/       keyboard label definitions
Language/     translation files
Database/     Eloquent models + migrations
bin/          CLI tools (tgbase, scheduler)
docs/         documentation (you are here)
tests/        offline + live test suite
```

كل شيء داخل `App/` يصلك عبر حفنة من أصناف الدخول: `Core` (أوضاع التشغيل)، و`Processor` (توزيع التحديثات)، و`QueueManager` (وسطاء قوائم الانتظار)، و`SessionManager` (حالة كل محادثة)، و`Keyboard` (لوحات مفاتيح سلسة)، و`LogHandler` (التسجيل). والباقي هو التوصيلات التي يحتاجها هؤلاء الخمسة.
