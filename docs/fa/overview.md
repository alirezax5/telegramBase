# نمای کلی — TelegramBase چیست

## نسخهٔ یک‌جمله‌ای

TelegramBase یک فریمورک PHP است که «صحبت با Telegram Bot API» را به «نوشتن کلاس‌های پلاگین کوچک» تبدیل می‌کند و در همان حال همهٔ آنچه ربات‌های قابل‌اعتماد به آن نیاز دارند را مدیریت می‌کند: دریافت آپدیت‌ها، اعتبارسنجی وبهوک، صف‌بندی، تلاش مجدد و چرخهٔ عمر پروسه.

## چه کاری انجام می‌دهد

هر ربات تلگرامی — فارغ از میزان سادگی‌اش — به یک اسکلت یکسان نیاز دارد:

1. **دریافت آپدیت‌ها.** یا شما از تلگرام می‌پرسید «چیز جدیدی هست؟» (long-polling از طریق `getUpdates`)، یا تلگرام به URL HTTPS شما درخواست می‌زند (وبهوک). TelegramBase هر دو را پشتیبانی می‌کند و انتخاب تنها با یک مقدار `.env` انجام می‌شود.
2. **اعتبارسنجی درخواست‌های وبهوک.** هر کسی می‌تواند آپدیت‌های جعلی به URL شما POST کند. TelegramBase پیش از آنکه حتی یک خط از کد شما اجرا شود، حجم بدنهٔ درخواست، IP مبدأ (ساب‌نت‌های رسمی تلگرام)، توکن مخفی اختیاری و درستیِ ساختار JSON را بررسی می‌کند.
3. **مسیریابی آپدیت‌ها به کد شما.** یک `Processor` شیء خام آپدیت را نرمال‌سازی می‌کند و آن را به هر پلاگینی که فیلترهایش با آن مطابقت دارند (نوع چت، ترتیب اولویت)، به‌صورت اختیاری از طریق یک پایپ‌لاین میدلور تحویل می‌دهد.
4. **مقاومت در برابر خرابی.** فراخوانی‌های API می‌توانند `429 Too Many Requests` برگردانند. هندلرها می‌توانند استثنا پرتاب کنند. ورکرها ممکن است وسط پردازش یک آپدیت کشته شوند. برکرهای صف می‌توانند از دسترس خارج شوند. TelegramBase برای هر یک پاسخی دارد: صف تلاش مجدد با backoff نمایی (با احترام به `retry_after` تلگرام)، اندازه‌های محدود برای صف، اتصال مجدد برکر با backoff، و تضمین‌های تحویل مستندشده برای هر حالت.
5. **مقیاس‌پذیری در صورت نیاز.** با یک پروسهٔ واحد `php bot.php` شروع کنید. وقتی حجم پردازش سنگین می‌شود، به پایپ‌لاین صف سوئیچ کنید: یک fetcher سبک آپدیت‌ها را در Redis/RabbitMQ قرار می‌دهد و پروسه‌های ورکرِ جداگانه آن‌ها را مصرف می‌کنند.

TelegramBase تمام این کارها را انجام می‌دهد و یک سطح API کوچک، ساده و قابل‌تست را در اختیار شما می‌گذارد.

## چه کارهایی آگاهانه انجام نمی‌دهد

- **یک SDK ربات نیست.** فراخوانی‌های واقعی Telegram API از [`alirezax5/telegram-bot-php`](https://github.com/alirezax5/telegram-bot-php) می‌آیند (همان شیء `Telegram` که به پلاگین‌های شما تزریق می‌شود). TelegramBase لایهٔ *پیرامون* آن SDK است.
- **منطق ربات شما را نمی‌نویسد.** هیچ «سازندهٔ مکالمه» یا پنل مدیریتی وجود ندارد. شما کلاس‌های سادهٔ PHP می‌نویسید؛ فریمورک آن‌ها را زمان‌بندی و تغذیه می‌کند.
- **PHP را پنهان نمی‌کند.** نه DSL سفارشی دارد و نه تعاریف ربات به‌صورت YAML. اگر PHP 8 و Telegram Bot API را بشناسید، طرز کار TelegramBase را هم می‌دانید.

## فلسفهٔ طراحی

- **پیکربندی به‌جای کد.** حالت عملیات، بک‌اند صف، درایور کش، زبان — همه از طریق `.env` تغییر می‌کنند، نه با ویرایش کلاس‌ها.
- **اجزای ساده و شناخته‌شده.** سشن‌ها، کش و قفل‌ها روی Illuminate ساخته شده‌اند (`illuminate/cache`، `illuminate/database`). این‌ها همان اجزایی هستند که Laravel در پروداکشن استفاده می‌کند؛ TelegramBase هیچ وابستگی عجیبی اضافه نمی‌کند.
- **صادق دربارهٔ خرابی.** هر مسیر پردازش یک تضمین تحویل مستندشده دارد (at-least-once یا at-most-once) — که با کشتن ورکرهای واقعی با SIGKILL در طول تست یکپارچگی اندازه‌گیری شده است، نه حدس زده‌شده. جزئیات در [reliability.md](reliability.md) آمده است.
- **خرابی پرسروصدا، نه بی‌سروصدا.** حالت فقط-CLI روی یک نقطهٔ ورود وب، HTTP 500 را همراه با توضیح برمی‌گرداند، به‌جای آنکه بی‌صدا معلق بماند. صفِ پر، pushهای جدید را رد کرده و لاگ می‌کند، به‌جای آنکه دیسک شما را ببلعد.

## شکل کدبیس

```
App/          the framework (one concern per subdirectory)
Plugin/       YOUR plugins (auto-discovered)
Button/       keyboard label definitions
Language/     translation files
Database/     Eloquent models + migrations
bin/          CLI tools (tgbase, scheduler)
docs/         documentation (you are here)
tests/        offline + live test suite
```

همه‌چیز در `App/` از طریق چند کلاس ورودی محدود به شما ارائه می‌شود: `Core` (حالت‌های اجرا)، `Processor` (توزیع آپدیت)، `QueueManager` (بک‌اندهای صف)، `SessionManager` (وضعیت هر چت)، `Keyboard` (کیبوردهای fluent)، `LogHandler` (لاگ‌گیری). باقی‌ماندهٔ کد همان لوله‌کشی‌هایی است که این پنج مورد به آن نیاز دارند.
