# دستورپخت — الگوهای مستخرج از یک دیپلوی واقعی

راه‌حل‌های کوتاه و تصمیم‌دار برای سؤال‌هایی که هنگام ساخت و ادارهٔ یک ربات
پشتیبانی واقعی (رلهٔ کاربر↔ادمین، پنل ادمین، گروه رله) روی telegramBase
واقعاً پیش آمد. هر دستور به یک نمونهٔ قابل‌اجرا در
[examples/](../../examples/) لینک دارد.

## دستور ۱ — رلهٔ پشتیبانی با سینک ویرایش زنده

*کاربر در پیوی می‌نویسد → کپی در گروه رله می‌افتد → ادمین با Reply روی کپی
پاسخ می‌دهد → پاسخ در چت کاربر می‌نشیند. اگر کاربر پیامش را ویرایش کند کپیِ
گروه هم ویرایش می‌شود؛ اگر ادمین پاسخش را ویرایش کند کپیِ کاربر هم ویرایش
می‌شود.*

نکات کلیدی:

1. وب‌هوک «باید» `edited_message` داشته باشد — `php bin/tgbase webhook:info`
   وقتی ندارد هشدار می‌دهد (تلگرام فقط انواع allowed را تحویل می‌دهد).
2. PluginHandler `edited_message` را خودکار به `onEditedMessage($msg, $tg)`
   می‌رساند — همان قواعد priority/ChatType که `onMessage`.
3. نقشهٔ کوچک شناسه‌ها را ذخیره کنید: `user_msg_id → group_copy_id` و
   `group_msg_id → {user_chat, user_copy_id}`. شروع با فایل JSON
   (LOCK_EX) کافی است؛ برای حجم به جدول DB بروید.
4. هنگام ویرایش کپی‌ای که کیبورد اینلاین دارد، `reply_markup` قبلی را دوباره
   بدهید — وگرنه ویرایش کیبورد را حذف می‌کند.

نمونهٔ کامل: [examples/RelayEditSyncBot.php](../../examples/RelayEditSyncBot.php).
پیاده‌سازی پروداکشن (payam) همان شکل را با ردیف DB `pm_messages` دارد.

## دستور ۲ — پنلی که ادمین را گیر نمی‌اندازد

*هر state ورودی‌گیر باید خروجِ پیدا داشته باشد؛ ترک فلو باید کیبورد را
تمیز کند.*

1. صفحه‌های پنل را با **MenuFlow** بسازید (ببینید
   [menu-flows.md](menu-flows.md)) — بازگشت/خانه مجانی‌اند.
2. دست‌ساز؟ پس: روی هر کیبورد پرامپت ردیف «↩️ بازگشت / ❌ کنسل» رندر کنید،
   این برچسب‌ها را «قبل از» ماشین وضعیت تطبیق دهید و هنگام رهاکردن state،
   `Keyboard::remove()` را به یک پیام بچسبانید.
3. تطبیق برچسب کیبورد را از متر جمین بگذرانید
   (`Conversation::textMatches()`) تا زبان‌امن باشد.

نمونهٔ کامل: [examples/PanelBot.php](../../examples/PanelBot.php).

## دستور ۳ — پنل فقط در پیوی، گروه فقط پاسخ

*قرارداد محصول ربات پشتیبانی: منو در پیوی است (فقط ادمین)؛ گروه رله برای
پاسخ دادن است نه منو؛ `/panel` در گروه عمداً بی‌پاسخ است.*

1. `#[ChatType(['private'])]` روی پلاگین پنل + گیت صریح ادمین
   (`ADMIN_IDS` یا جدول users) — هرگز به گروه برای کار ادمین تکیه نکنید.
2. در پلاگین گروه فقط وقتی عمل کنید که `$msg->reply_to_message` وجود دارد و
   پاسخ‌دهنده ادمین است؛ بقیه از پلاگین عبور می‌کند.
3. برای گروه هندلر `/panel` ثبت نکنید — سکوت، رفتار مستند است.

## دستور ۴ — دیباگِ «پیام هرگز نرسید»

1. `LOG_API_TRACE=1` → برای هر فراخوانی API یک خط:
   `📡 sendMessage → FAIL 91ms chat 123 | 403 Forbidden: bot was blocked…`
2. `php bin/tgbase webhook:info` → وب‌هوک ست است؟ تعداد pending؟
   last_error؟ آیا `allowed_updates` انواع لازم را دارد؟
3. آپدیت دقیق را آفلاین پخش کنید: ذخیره به‌صورت JSON و
   `php bin/tgbase simulate fixture.json --dry` (فقط پارس) یا بدون `--dry`
   روی ربات تست تا از پایپ‌لاین واقعی عبور کند.
4. `.env` را دستی ویرایش کردید؟ مالکیت را چک کنید: کاربر FPM باید بتواند
   بخواندش (در ستاپ‌های معمول aaPanel/BT: `chown www:www .env`) —
   `.env` با 640 و مالک root، خطای 500 «BOT_TOKEN is not set» می‌دهد که
   هرگز به لاگ اپ نمی‌رسد.

## دستور ۵ — چک‌لیست بهداشت کیبورد (قرارداد TM-25)

- [ ] هر کیبورد پرامپت ردیف بازگشت/کنسل دارد
- [ ] برچسب کنسل از متر جمین می‌گذرد و بعد خروجِ تمیز انجام می‌شود
- [ ] رهاکردن فلو `remove_keyboard` می‌فرستد (به پیام بعدی بچسبانید)
- [ ] `editMessageText()` مقدار `reply_markup` قبلی را دوباره می‌فرستد
- [ ] جایگزینی صفحه با کیبورد جدید خودبه‌خود کیبورد قبلی را عوض می‌کند —
      remove دوباره لازم نیست

## دستور ۶ — نقطهٔ ورود مینی‌اپ

1. دکمه را بسازید: `Keyboard::reply()->webApp('فروشگاه', $url)` یا نسخهٔ
   اینلاین (ببینید [buttons.md](buttons.md)).
2. مینی‌اپ هنگام لود `WebApp.initData` می‌گیرد — قبل از اعتماد به کاربر،
   سمت سرور (HMAC-SHA256 طبق داکیومنت تلگرام) اعتبارسنجی کنید.
3. بک‌اند ربات منبع حقیقت بماند؛ مینی‌اپ فقط یک نما است. (پشتیبانی بومی
   اعتبارسنجی initData برای فریم‌ورک در حال ارزیابی است — وضعیت فعلی را در
   README ریپو ببینید.)
