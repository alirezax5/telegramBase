# i18n — Language

Translation files, the `__()` helper, and automatic caching of compiled language maps.

```php
use alirezax5\TelegramBase\App\Language\Language;
```

## File layout

Everything lives under `LANG_DIR` (default `/Language`, resolved against the project base — `Bootstrap` wires `Paths::base() . LANG_DIR` for you).

```
Language/
├── fa.php            # main file for 'fa' — keys as-is
└── fa/               # optional subdirectory — keys get a '<filename>.' prefix
    ├── main.php      #   → main.ali, main.other, …
    └── buttons.php   #   → buttons.save, buttons.cancel, …
```

- The **main file** is `{LANG_DIR}/{lang}.php`; the **subdirectory** is `{LANG_DIR}/{lang}/` and every file in it is loaded alphabetically with the file basename as key prefix.
- Nested arrays are flattened to **dot notation**: `['btn' => ['btna' => 'hi']]` → `btn.btna`.
- File format follows `LANG_DRIVER`:

> ⚠️ **`LANG_DRIVER` must match your file format.** The default is `json`, but the repo ships PHP-array files (`fa.php`, `fa/main.php`) and `.env.example` sets `LANG_DRIVER="php"`. With the mismatch (json driver + .php files) every lookup silently falls back to the key name — no error, just untranslated text. This exact scenario was reproduced during the P-CACHE live tests: `__('key')` returned `"key"` until `LANG_DRIVER=php` was set.

```dotenv
LANG_DRIVER=php        # json | php — format of the language files
DEFAULT_LANG=fa        # boot language (Persian, RTL)
LANG_DIR=/Language
LANG_CACHE_TTL=60      # seconds the compiled map stays in cache
```

## The `__()` helper

```php
// translations: 'welcome' => 'سلام #name خوش آمدی'
__('welcome', ['name' => 'علی']);          // "سلام علی خوش آمدی"
__('missing_key', 'پیش‌فرض');              // fallback when the key is absent
__('missing_key');                          // falls back to the key name itself
```

Replacements use the `#placeholder` syntax; the map keys are written without the `#`:

```php
__('greeting', 'default', ['name' => $firstName, 'count' => 3]);
```

Language singleton:

```php
$lang = Language::getInstance();

$lang->setLanguage('en');        // switch language (per process — call it per update if users differ)
$lang->get('key', $default, $replacements);
$lang->has('key');               // exists in the current language?
$lang->getAll();                 // full flat map
$lang->getCurrentLanguage();

$lang->reloadLanguage('fa');     // drop cache + re-read files
$lang->clearCache();             // forget lang:* cache keys
$lang->getCacheStats();          // per-language entry counts + freshness
```

## Per-user language in a plugin

`Language` is a per-process singleton — the current language applies to everything that runs after `setLanguage()` in that process. For per-user language selection (webhook/queue deployments), resolve and set it at the top of the handler:

```php
$userLang = $session->get('lang', 'fa');          // or read from your users table
Language::getInstance()->setLanguage($userLang);
$tg->sendMessage($chatId, __('menu_title'));
```

In a single-process polling daemon, a mid-update switch leaks to subsequent updates unless you switch back — prefer setting it per update unconditionally.

## Caching behavior (verified)

The first load of a language reads the files, flattens the map, and stores it under the cache key `lang:{lang}` with `LANG_CACHE_TTL`. Subsequent loads (including fresh processes) hit the cache — the P-CACHE run showed the full payload (`{"key":"value","btn.btna":"hi","main.ali":"asfaf132"}`) surviving cross-process on `file`, `redis` and `memcached`, with the backend TTL counting down from exactly 60 s. Missing translation keys are tracked in `lang:missing_keys` and flushed once per update iteration (`Core::cleanup()` → `flushMissingKeys()`), which makes debugging untranslated strings trivial — check the cache/logs for the key list.

## Scaffolding

```bash
php bin/tgbase make:language en     # creates Language/en.php scaffold
```

`Language/fa.json.example` shows the JSON format if you prefer JSON files (then set `LANG_DRIVER=json`).


## Lazy `filename.key` loading (2026-10)

A miss on a dot-key (e.g. `__('shop.open')`) now tries
`Language/{lang}/shop.{php,json}` once and merges it — files added after
the language cache was built (or during a stale TTL window) resolve
transparently, without a reload. Unknown prefixes fall straight back to
the default; the attempt happens at most once per prefix per request.
