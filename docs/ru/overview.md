# Обзор — что такое TelegramBase

## Версия в одном предложении

TelegramBase — это PHP-фреймворк, который превращает «общение с Telegram Bot API» в «написание небольших классов-плагинов», беря на себя всё, что нужно надёжным ботам: получение обновлений, валидацию вебхуков, постановку в очередь, повторные попытки и жизненный цикл процессов.

## Что он делает

Каждому Telegram-боту — каким бы простым он ни был — нужен один и тот же скелет:

1. **Получать обновления.** Либо вы спрашиваете у Telegram «есть что-то новое?» (long-polling через `getUpdates`), либо Telegram сам обращается к вашему HTTPS-URL (вебхук). TelegramBase поддерживает оба варианта, выбор делается одним значением в `.env`.
2. **Валидировать запросы вебхука.** Кто угодно может отправить POST-запрос с поддельными обновлениями на ваш URL. TelegramBase проверяет размер тела, IP-адрес источника (официальные подсети Telegram), необязательный секретный токен и корректность JSON ещё до того, как ваш код вообще запустится.
3. **Маршрутизировать обновления в ваш код.** `Processor` нормализует сырой объект обновления и передаёт его каждому плагину, чьи фильтры совпали (тип чата, порядок приоритетов), при необходимости через конвейер промежуточного ПО (мидлварь).
4. **Переживать сбои.** Вызовы API могут возвращать `429 Too Many Requests`. Хендлеры могут выбрасывать исключения. Воркеров могут убить посреди обработки обновления. Брокер очереди может выйти из строя. Для каждого такого случая у TelegramBase есть своё решение: очередь повторных попыток с экспоненциальной задержкой (с учётом `retry_after` от Telegram), ограниченный размер очереди, переподключение к брокеру с задержкой и документированные гарантии доставки для каждого режима.
5. **Масштабироваться, когда нужно.** Начните с одного процесса `php bot.php`. Когда нагрузка станет существенной, переключитесь на конвейер очереди: лёгкий фетчер отправляет обновления в Redis/RabbitMQ, а отдельные процессы-воркеры потребляют их.

TelegramBase делает всё это и предоставляет небольшой, скучный, тестируемый API-интерфейс.

## Чего он сознательно не делает

- **Это не SDK для бота.** Реальные вызовы Telegram API выполняет [`alirezax5/telegram-bot-php`](https://github.com/alirezax5/telegram-bot-php) (объект `Telegram`, внедряемый в ваши плагины). TelegramBase — это слой *вокруг* этого SDK.
- **Он не пишет логику вашего бота.** Здесь нет «конструктора диалогов» или админ-панели. Вы пишете обычные PHP-классы, а фреймворк планирует их запуск и передаёт им данные.
- **Он не прячет PHP.** Никакого собственного DSL, никаких YAML-описаний ботов. Если вы знаете PHP 8 и Telegram Bot API — вы знаете, как устроен TelegramBase.

## Философия дизайна

- **Конфигурация вместо кода.** Режим работы, бэкенд очереди, драйвер кэша, язык — всё переключается через `.env`, а не правкой классов.
- **Скучные компоненты.** Сессии, кэширование и блокировки построены на Illuminate (`illuminate/cache`, `illuminate/database`). Это те же компоненты, которые Laravel использует в продакшене; TelegramBase не добавляет никаких экзотических зависимостей.
- **Честность в отношении сбоев.** У каждого пути обработки есть документированная гарантия доставки (at-least-once или at-most-once) — измеренная на реальном убийстве воркеров через SIGKILL во время интеграционного тестирования, а не угаданная. См. [reliability.md](reliability.md).
- **Падать громко, а не молча.** Режим «только CLI» на веб-точке входа вернёт HTTP 500 с объяснением, а не будет молча висеть. Переполненная очередь отклоняет и логирует новые записи, а не «съедает» ваш диск.

## Устройство кодовой базы

```
App/          the framework (one concern per subdirectory)
Plugin/       YOUR plugins (auto-discovered)
Button/       keyboard label definitions
Language/     translation files
Database/     Eloquent models + migrations
bin/          CLI tools (tgbase, scheduler)
docs/         documentation (you are here)
tests/        offline + live test suite
```

Всё содержимое `App/` доступно вам через несколько входных классов: `Core` (режимы запуска), `Processor` (диспетчеризация обновлений), `QueueManager` (бэкенды очередей), `SessionManager` (состояние по чатам), `Keyboard` (флюент-клавиатуры), `LogHandler` (логирование). Остальное — обвязка, которая нужна этим пяти.
