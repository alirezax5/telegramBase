# Кэширование — CacheManager

Один статический API над четырьмя взаимозаменяемыми драйверами, конфигурируемый полностью через `.env`. Сессии, переводы, определения кнопок и (опционально) обнаружение плагинов — всё это работает поверх данного слоя; смена драйвера меняет историю персистентности всего фреймворка, не затрагивая код.

```php
use alirezax5\TelegramBase\App\Cache\CacheManager;
```

> Каждое утверждение в этом документе было проверено вживую (2026-10-11) на реальных бэкендах продакшен-сервера: набор из 17 проверок прошёл зелёным на `array`, `file`, `memcached` (PHP 8.5) и `redis`, плюс матрица кросс-процессной персистентности из 9 пунктов для каждого персистентного драйвера. См. раздел *Live verification* внизу и [CHANGELOG](../../CHANGELOG.md).

## Драйверы

| `CACHE_DRIVER` | Бэкенд | Кросс-процессность | Теги | Примечания |
|---|---|---|---|---|
| `array` (по умолчанию) | память на процесс | ✗ | ✗ | нулевая настройка; состояние живёт ровно столько, сколько живёт процесс |
| `file` | диск, `CACHE_PATH` | ✓ | ✗ | без дополнительных сервисов; хэшированные 2-уровневые каталоги; полезная нагрузка в PHP-сериализации |
| `redis` | расширение phpredis (`redis.so`) | ✓ | ✗ | полезная нагрузка в JSON; рекомендуется для многопроцессных развёртываний |
| `memcached` | расширение `memcached` + сервер | ✓ | ✗ | полезная нагрузка в JSON; по своей природе непостоянен |

**Цепочка отката (проверена):** если запрошенный драйвер недоступен — расширение отсутствует, сервер недостижим, аутентификация не прошла, путь не доступен для записи — фреймворк логирует предупреждение и **откатывается к `array`** вместо провала загрузки. Запрос `memcached` на PHP без расширения дал ровно это: `driver=array`, всё остальное без изменений. Проверить, что вы фактически получили, можно через `CacheManager::getDriver()`.

> ⚠️ Драйвер `array` локален для процесса. Polling-демон — это *один* долгоживущий процесс, поэтому `array` там «работает»; но вебхук (FPM-воркеры на запрос) и воркеры очереди (один процесс на воркера) никогда не разделяют состояние. Если сессии, счётчики или `remember()` должны переживать сообщения/процессы, используйте `file`, `redis` или `memcached`. Это было продемонстрировано вживую: значения, записанные в процессе A и прочитанные в процессе B, — сохраняются на всех трёх, `<MISS>` на `array` (так задумано).

## Конфигурация (.env)

```dotenv
CACHE_DRIVER=file            # array | file | redis | memcached
CACHE_PREFIX=tgbase_         # key namespace (also the flush() safety boundary)
CACHE_TTL=3600               # default TTL seconds when put() has no explicit ttl
CACHE_PATH=/tmp/tgbase-cache # file driver only
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=              # required if the server has requirepass (NOAUTH otherwise)
REDIS_DATABASE=0
MEMCACHED_HOST=127.0.0.1
MEMCACHED_PORT=11211
```

## API

| Метод | Поведение |
|---|---|
| `get($key, $default = null)` | значение или default при промахе/истечении |
| `put($key, $value, ?int $ttl = null)` | сохранить; `null` ttl → `CACHE_TTL` |
| `remember($key, callable $cb, ?int $ttl = null)` | вернуть кэшированное значение или выполнить `$cb`, закэшировав результат |
| `has($key)` | существует и не истёк |
| `forget($key)` | удалить один ключ |
| `flush()` | удалить **все ключи неймспейса этого фреймворка** — см. примечания по драйверам |
| `increment($key, $by = 1)` / `decrement($key, $by = 1)` | счётчики |
| `getDriver()` / `isInitialized()` / `tagsSupported()` | интроспекция |
| `putWithTags()` / `getWithTags()` / `rememberWithTags()` / `flushTags()` | tag-стиль API, работающий на каждом драйвере (откат на основе префикса) |
| `tags([...])` | нативный tagged cache — **выбрасывает исключение**, если драйвер не поддерживает теги (ни один из четырёх не поддерживает) |

### Семантика TTL (проверена реальными ожиданиями)

`put('k', 'x', 2)` → `has` true → через 3 с → `has` false, `get` возвращает default. TTL бэкендов совпадают с конфигом в точности: запись на 300 с показала `ttl=297s` в `redis-cli`, сессия на 3600 с — `ttl=3597s`, кэш переводов на 60 с — `ttl=57s`. Истёкшие записи в `file`/`redis` удаляются лениво (при обращении) или самим бэкендом (`redis` setex).

### Форматы хранения

- **redis** — `setex` с `json_encode(JSON_UNESCAPED_UNICODE)`. Полезная нагрузка должна переживать JSON-преобразование туда и обратно: скаляры и массивы — да; PHP-объекты возвращаются массивами; ресурсы — нет.
- **memcached** — JSON через то же семейство методов хранения; значения прозрачно (де)сериализуются расширением.
- **file** — полезная нагрузка через PHP `serialize()`, сначала отметка истечения, в `CACHE_PATH/ab/cd/<sha1>`.
- **array** — обычные PHP-переменные; ничего не касается диска или сети.

### Раскладка ключей (сырой вид бэкенда)

| Драйвер | Сырой ключ для `put('lang:fa', …)` при `CACHE_PREFIX=tgbase_` |
|---|---|
| redis | `tgbase_lang:fa` |
| memcached | `tgbase_:lang:fa` (Illuminate добавляет `:` к префиксу) |
| file | `CACHE_PATH/<h1>/<h2>/<sha1>` |

### Счётчики — один нюанс (проверен)

`increment()` по **отсутствующему** ключу: `array`/`file`/`redis` создают его (`incBy`), `memcached` возвращает `false` (Illuminate не отправляет начальное значение). Переносимый паттерн: сначала инициализируйте — `CacheManager::put($k, 0, $ttl); CacheManager::increment($k);`

### flush() — охват по драйверам

- `array` — только этот процесс.
- `file` — всё внутри `CACHE_PATH` (выделенный каталог; безопасно).
- `redis` — **ограничено префиксом**: итерирует через `SCAN` по `{CACHE_PREFIX}*` и делает `UNLINK` только этих ключей. Безопасно на разделяемых инстансах (проверено на Redis, разделяемом с object cache WordPress — остальные ключи не тронуты). Отказывается выполняться с пустым префиксом.
- `memcached` — ⚠️ `MemcachedStore::flush()` выполняет серверный `flush_all`. На **разделяемом** memcached это стирает кэш других приложений — не делайте этого там (набор тестов сознательно пропускает).

## Что работает поверх кэша

| Потребитель | Ключ | Регулятор TTL |
|---|---|---|
| [Сессии](sessions.md) | `tgbase:session:{chatId}` | `SESSION_TTL` (по умолчанию 3600, минимум 60) |
| [Переводы](i18n.md) | `lang:{lang}`, `lang:missing_keys` | `LANG_CACHE_TTL` (по умолчанию 60) |
| [Определения кнопок](buttons.md) | `buttons:all` | `BUTTONS_CACHE_TTL` (по умолчанию 300), выключатель `BUTTONS_CACHE_ENABLED` |
| Обнаружение плагинов | (внутренний) | `PLUGIN_CACHE_ENABLED` + `PLUGIN_CACHE_TTL` |

## Живая верификация (P-CACHE, 2026-10-11)

| Набор | Результат |
|---|---|
| 17-проверочный in-process набор × `array` / `file` / `memcached` (PHP 8.5) / `redis` | **PASS** на всех |
| memcached запрошен на PHP 8.4 (без расширения) → корректный откат к `array` | **PASS** (задокументированная цепочка) |
| Кросс-процессная матрица (`set` процесс → `get` процесс): скаляр, вложенный массив, счётчик 5→6, `remember` возвращает *заложенный* random, непрерывность id и полезной нагрузки сессии, полезная нагрузка `lang:fa`, полезная нагрузка `buttons:all` | **9/9 PASS** на `file`, `redis`, `memcached`; `array` промахивается ровно как задокументировано |
| Инспекция бэкендов | redis-ключи с живым обратным отсчётом TTL; сырые ключи memcached под `tgbase_:`; file-хранилище с видимыми отметками истечения |
| Реальный конвейер: `/cache demo hello` (диспетчеризация 1) → `/cache demo` (диспетчеризация 2, свежий процесс) → `demo = hello`; `/session-set`/`/session-get` так же | **PASS** |

Одна реальная ошибка была найдена и исправлена этим упражнением: **`CacheRedisStore::flush()` завершал свой SCAN-цикл на первой пустой странице MATCH** (частое явление на разделяемых/больших пространствах ключей) — ничего не удаляя, но возвращая `true` (P-CACHE-F001 в CHANGELOG).
