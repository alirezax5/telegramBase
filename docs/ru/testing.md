# Тестирование — офлайн-набор, живые тесты и CI

## Офлайн-набор тестов

Фреймворк поставляется с тест-раннером, не требующим зависимостей (PHPUnit не нужен):

```bash
composer install        # vendor/ must exist (the suite boots the framework)
php tests/run.php
```

Структура:

| Каталог | Что там живёт |
|---------|----------------|
| `tests/Unit/` | чистые юнит-тесты — env-хендлер, конфиг, драйверы очереди, хранилище смещений, валидация webhook-диспетчера, связка middleware, жизненный цикл повторов, ... (без сети) |
| `tests/Integration/` | многокомпонентные тесты (по-прежнему офлайн) |
| `tests/Live/` | **реальные тесты Telegram API — только по явному включению** (см. ниже) |
| `tests/smoke.php` | автономный smoke-тест бутстрапа (плохой токен, пустой токен, плохой режим, корректная загрузка) |
| `tests/benchmark.php` | микро-бенчмарки горячих путей |

Фильтрация по имени:

```bash
php tests/run.php --filter=Keyboard
php tests/run.php --filter=Queue
```

## Известный дрейф набора — РЕШЕНО

До v2.4.0 офлайн-прогон сообщал **196 pass / 18 fail / 12 skip**. 18 сбоев (`SessionTest` ×10, `BackwardCompatTest` ×4, `MiddlewareWiringTest` ×4) были заранее существующими, и было доказано, что они не связаны с исправлениями фреймворка, путём отката каждого исправления и повторного прогона.

Корневая причина была найдена во время предрелизного обзора (P-REL-B05): `tests/run.php` засеивает значения env по умолчанию и вызывает `Bootstrap::boot()`, но `EnvironmentBootstrap` использовал `load()` из Dotenv, который **выбрасывает исключение, когда в репозитории нет `.env`** (свежий клон поставляется только с `.env.example`). Загрузка прерывалась, `Config` оставался неинициализированным, и каждый зависящий от конфига тест падал. После перехода на `safeLoad()` набор идёт зелёным в свежем клоне без какой-либо настройки:

```
Pass: 224  Fail: 0  Skip: 12
```

## Живые тесты Telegram

Живые тесты обращаются к реальному Bot API и пропускаются, если явно не включены:

```bash
RUN_TELEGRAM_LIVE_TESTS=1 \
TELEGRAM_BOT_TOKEN="<your-token>" \
TELEGRAM_TEST_CHAT_ID="<your-chat-id>" \
php tests/run.php
```

Внутренние правила (обеспечиваются самими тестами):

- каждое отправляемое ими сообщение помечено тегом `[telegramBase automated test]`
- после проверки они удаляют собственные сообщения, где это возможно — и никогда не удаляют сообщения, которые не создавали
- включены негативные пути: недопустимый чат, недопустимый токен, симуляция 429
- токен читается **только** из переменных окружения

## CI (GitHub Actions)

`.github/workflows/tests.yml` запускается на каждый push/PR на PHP **8.1 – 8.4**: валидация composer, `composer audit` и офлайн-набор.

`.github/workflows/live-tests.yml` — **ручной** (`workflow_dispatch`) workflow для живых тестов; он читает токен из секрета репозитория `TGBASE_LIVE_BOT_TOKEN` и входной параметр `chat_id` — никаких секретов в файле workflow, и дефолтный CI никогда не касается секретов.

## Smoke-тест

```bash
php tests/smoke.php
```

Шесть случаев: плохой токен / пустой токен / попытка log-traversal / абсолютный путь лога / плохой режим / корректная загрузка. Используйте его после развёртываний как 5-секундную проверку здоровья.

## Что покрывает набор (и почему это важно для доверия)

Утверждения о надёжности в [reliability.md](reliability.md) подкреплены тестами плюс crash-проверенными интеграционными сценариями (SIGKILL на каждом этапе конвейера, реальные проверки повторной доставки брокера, тесты переходов вебхука с верификацией через `getWebhookInfo`). Наиболее релевантные наборы для аудита этих утверждений:

```bash
php tests/run.php --filter=Queue      # driver behaviour (json/redis/rabbitmq contracts)
php tests/run.php --filter=Offset     # offset storage atomicity
php tests/run.php --filter=Retry      # retry queue lifecycle + retry_after
php tests/run.php --filter=Webhook    # the 5 webhook validation layers
php tests/run.php --filter=Security   # env/log hardening rules
```

Интеграционный стенд, использовавшийся во время crash-тестирования (реальный бот + сценарные скрипты), живёт в `integration/TestBot/` — см. его README о том, что он делает и как адаптировать его под своё развёртывание.
